## A switch in the same game

1. **Prepare and admit.** Keep the selected local asset commit, derivation, stable semantic ID, display bucket and payload bound at offline publication. Add one optional HD pair beside the admitted baseline, under a separate optional field keyed by the same `identity-icon.item.0.normal` and `.selected` identities. The existing reader requires 16×24 base frames, paired keys and valid digests. Give the HD pair its own checked 64×96 shape, format, pairing and payload identity; passing a large image through the base reader would fail. The independent R&D checkout has no runtime role. [Asset ownership and current publication](presentation-assets.md#spell-and-item-identity-art-1667) · [Content reader](../../src/Sf2.Remake.Content/Scenarios/IdentityIconReader.cs)
2. **Apply at the host.** Offer Original / HD in ordinary Settings with readable coverage, e.g. “HD · 1 field item; other art uses Original.” Default and old preference files select Original. Extend the current settings draft, copy/validation, Apply, Cancel, Restore defaults and read-only launch override. While the host has paused the session at an existing settings entry, prepare new textures, validate, persist the candidate, publish the selection and rebind/redraw mounted rows. Keep old handles until borrowers have switched. If preparation or persistence fails, keep the old visuals and preference and show the error. Later presenters resolve the saved choice when mounted. Full Settings currently opens from entry or an eligible field state; the battle Speed-only entry needs a separately scoped decision for any battle-time toggle. [Host](../../game/src/Entry/SettingsHost.cs) · [Preference store](../../game/src/Input/SettingsStore.cs)
3. **Resolve each identity.** In HD mode, use the reviewed pair if present; if absent, draw its admitted original pair. An absent baseline namespace in a public profile keeps its existing text presentation. A malformed declared pair is an admission error; never conceal a broken binding as ordinary fallback. Keep public builds on authored/licensed content. Expose applied mode and actual HD/original/text result for review. Reuse the existing texture owner and `IdentityIcon` draw rectangle. Field-only publication leaves battle on the original pair even for the same ID. [Presenter and texture lifetime](../../game/src/UI/IdentityIcons.cs)

Keep cell size (96 px), camera, anchor, draw order, collision, cursor/hit rectangles, selected inventory slot, phase, turn, RNG and animation frame/timing under their existing owners. Persist the choice in operator preferences across launch and save/load. Implementation can observe presenter state, input and errors on the running instance. ## First playable decision and cost

Take Medical Herb (ID 0) from the selected private pack, derive its normal/selected pair **locally**, and review it beside the originals before promoting either frame. The lantern never substitutes for the herb. Use one existing field inventory with a second uncovered identity and its existing public text case. At production size on light and dark surroundings, ask a player to identify the herb and distinguish selection without a label cue. Inspect holes, palette, outer rim and alignment against both original frames. Reject any broken transparent hole, lost selection cue, altered anchor or unexplained expansion beyond one display pixel. An overlap percentage alone cannot accept the art.

Toggle Original → HD → Original in one session, then reopen the same inventory, cancel a draft, relaunch and load the same slot. Observe unchanged item/slot, dimensions, input target and session state across Apply, actual texture selection and fallback for the uncovered item, override/write-failure behavior, persisted mode, and absence of adapter errors. Use existing running-instance state/input observations plus human viewing. Stop at this one field pair until the player accepts it. If recognition or registration fails, retain Original and return the pair for revision.

**Planning estimate:** assuming the existing world publisher and field UI owner suffice, allow ½ day for pair preparation/review and 1–2 developer days for admission, host wiring and observation. Two 64×96 RGBA frames occupy 48 KiB decoded per pair (vs. 3 KiB at 16×24); allow two copies briefly at swap plus decoder/driver overhead. Offline filtering and decoding are linear in the pixels processed. A field-only variant in one world adds about 64 KiB base64 before metadata if raw RGBA is embedded; avoid republishing seven battle copies. In the proxy trial the cloud master was 1,828,322 bytes, the delivered C was 8,511 bytes, B was 742 bytes, and the single edit returned in about 23 seconds. Per-call billing, GPU residency and live switch latency were not measured. First slice budgets zero cloud edits of private art. Allow at most one half-day art revision before reviewing scope; stop if a fresh asset platform or whole-scene reload would be needed.

**Unknown:** animation and tiling. Before admitting a moving family, overlay matching directions and play a full cycle locally; inspect feet, weapon/body layers, contact frame and flicker at original timing. Before admitting a tile family, repeat neighbors across a seam at 1×/4×, scroll across it and check roof/foreground occlusion on Map3. A failed family stays on its complete original frame set until reviewed. Neither family is admitted by this pilot.
