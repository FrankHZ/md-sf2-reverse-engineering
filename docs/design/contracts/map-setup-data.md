- **Confirmed original structure:** one ordered map-setup routing table, 64 map rows and 66 flag
  rows over the accepted map-ID domain `0..78`, 130 ordered setup references, 126 pointer-table
  identities, four default-pointer aliases, 126 six-slot setup definitions, and the bounded
  entity-list accessor chronology described below.
- **Inferred original behavior:** none promoted here. The typed route/definition model below is an

- Remake status: implementation-neutral Phase 3 private-import contract; no scene graph, story-state

  been selected.
- Evidence date: 2026-08-14

## Contract Boundary

This contract defines the static storage, reference, provenance, and private-import boundary for the
original map-setup routing corpus:

1. the ordered `MapSetups` routing-table serialization;
2. 64 map rows, 66 ordered flag rows, and their 130 pointer references;
3. 126 uniquely identified six-pointer setup definitions and four route aliases;
4. the six ordered target-slot identities in every setup definition;
5. the bounded `GetMapSetupEntityList` identity and source chronology;
6. a public aggregate projection that does not redistribute the complete route or pointer graph.

The sole executable owner consumed here is fixture id `sf2-map-setup-static-v1` in
[`tests/fixtures/h2/map-setup-static-v1.json`](../../../tests/fixtures/h2/map-setup-static-v1.json),
implemented by
[`src/sf2tool/h2/map_setup.py`](../../../src/sf2tool/h2/map_setup.py). Its owning research prose is
[Map Data Inventory and Binary Parity](../../research/map-data-inventory.md).

The consumed fixture surface is deliberately bounded to:

- `function.GetMapSetupEntityList` and `table.MapSetups` identity/address provenance;
- `expected.summary`;
- `expected.sourceFacts.pointerLayout`;
- only `expected.sourceFacts.selector.mapTableEndWord` and
  `expected.sourceFacts.selector.mapRowEndWord` as serialization terminator identities;

- route serialization, source order, table ownership, source/H1/ROM parity, and bounded provenance

## Ordered Route Serialization

**Confirmed static:** `MapSetups` begins at ROM `0x4F6E2` (`325346`). Its source-shaped serialized
grammar is:

```text
MapSetupRoutingTable := MapRow* 0xFFFF
MapRow              := mapWord defaultPointer FlagRow* 0xFFFD
FlagRow             := flagWord setupPointer
```

The words and pointers are big-endian source fields. Each map row contributes eight structural
bytes: a two-byte map word, a four-byte default pointer, and a two-byte row terminator. Each flag row
contributes a two-byte flag word and four-byte pointer. The complete byte count therefore closes as:

```text
64 * 8 + 66 * 6 + 2 = 910 bytes
```

The final two bytes are the table terminator. They are not a 65th map row or another flag row.

The accepted route surface contains:

| Surface | Confirmed count |
| --- | ---: |
| map rows | 64 |
| flag rows | 66 |
| ordered route references | 130 |
| routing bytes | 910 |
| complete routing-table source/ROM parity | 1 |

The `missingMapCount` value 15 is bounded to the verifier's accepted map-ID domain `0..78`, which
contains 79 IDs. It means fifteen IDs in that exact domain have no routing row. It is not a universal
map namespace, a claim about modified inputs, or proof that any path is naturally unreachable at
runtime.

A private importer MUST preserve map-row order, flag-row order within each map row, the default and
flag pointer identities, and both terminator identities. It MUST NOT normalize the source into an
unordered dictionary, discard a route because its pointer repeats, or infer story priority from a
flag number.

This contract preserves ordered route data, not selector ownership. The accepted
`GetCurrentMapSetup` source/H3 selection behavior, including the meaning of the ten tracked witness
cases, remains with [Map and Exploration](map-exploration.md). The witness cases may be exposed as
the already tracked public metadata, but they are not an H4 data-fidelity requirement and do not
create a second selector claim here.

## Alias and Definition Topology

**Confirmed static:** the 130 ordered route references resolve to 126 uniquely identified
pointer-table definitions. Four flag rows refer back to the default definition already named for
their map:

| Map | Flag | Referenced definition |
| ---: | ---: | --- |
| 7 | 702 | `ms_map7` |
| 33 | 783 | `ms_map33` |
| 33 | 22 | `ms_map33` |
| 40 | 507 | `ms_map40` |

The arithmetic closes as `130 - 126 = 4`. An importer MUST preserve these as four distinct ordered
route rows pointing to existing definition identities. It MUST NOT delete them as redundant or
materialize them as four invented definitions.

The count 126 means unique pointer-table identities/definitions in the accepted source and address
graph. It does not assert that all 24-byte table contents are pairwise different. Content equality,
if present, would not erase source symbol, address, path, or reference identity.

Each definition is 24 bytes: six ordered four-byte pointers. The complete pointer-table storage
boundary therefore closes as:

```text
126 * 6 = 756 pointer slots
126 * 24 = 3,024 pointer bytes
```

All 126 definition ranges match their accepted ROM bytes. The parity count is a per-definition
source/ROM relationship, not a license to publish the pointers, source paths, or target graph.

| Slot | Byte offset | Source identity |
| ---: | ---: | --- |

| 1 | 4 | `entityEvents` |

These names and offsets are static source identities. They define reference positions, not the
runtime meaning, side effects, persistence, presentation, or reachability of their targets.

A private importer MUST retain all 126 ordered definition identities and all 756 target references,
including each definition's source symbol, source path, ROM address, and target symbol/address. The
targets remain references to separately owned resources; they are not copied into each definition.

The complete definition/reference graph is private. Public evidence may retain the six slot names
and offsets, counts, byte totals, parity totals, fixture provenance, and the four already tracked
alias rows, but it MUST NOT publish the 126 symbols/addresses/source paths or the 756 target values.

## Entity-List Access Seam

**Confirmed static identity:** `GetMapSetupEntityList` begins at ROM `0x47790` (`292752`). The fixture
binds that address. Direct review of the pinned source preserves only this exact chronology:

1. branch-to-subroutine to `GetCurrentMapSetup`;
2. compare the word at selected `a0` with `-1`;
3. when equal, leave `a0` unchanged and return;
4. otherwise load the longword at offset 0 into `a0`;
5. return.

This establishes the bounded relationship between the selected definition, the void marker, and
slot 0. It does not import `GetCurrentMapSetup` selection behavior, describe `a0` as a modern API,
prove any caller's admission, or define what later code does with the returned entity-list pointer.

The underlying entity-list corpus remains with [Map Entity Data](map-entity-data.md). Runtime
population and reload remain with [Map and Exploration](map-exploration.md) and their accepted H3
owners. This contract does not consume those fixtures or turn their results into H4 requirements.

## H4 Acceptance Contract

A remake-facing H4 private importer passes this contract only when it can:

1. identify `sf2-map-setup-static-v1`, the pinned baseline, `MapSetups`, and
   `GetMapSetupEntityList` provenance;
2. preserve exactly 64 ordered map rows and 66 ordered flag rows using the accepted serialization,
   terminators, and 910-byte private source boundary;
3. preserve exactly 130 ordered definition references without replacing route rows with an
   unordered map or dropping repeated targets;
4. preserve 126 distinct source definition identities, six ordered target slots per definition,
   756 total slots, and 3,024 pointer bytes without claiming pairwise content uniqueness;
5. preserve the four exact default-definition aliases as distinct route rows and reject accidental
   alias flattening or invented definitions;
6. reproduce the six slot identities/offsets and keep every private target reference attached to its
   original definition and slot;
7. privately verify one routing-table and 126 definition source/H1/ROM parity relationships;
8. preserve the bounded entity-list accessor chronology without claiming selector, caller,
   population, or reload fidelity;
9. keep complete routes, symbols, addresses, source paths, target values, raw words/bytes, and
   underlying resource content outside public fixtures and reports;
10. report selector behavior, event/init execution, runtime lifecycle, persistence, story,
    presentation, malformed input, and replacement policy through separate owners or as **Unknown**.

Source/H1/ROM bytes, symbols, pointer values, and ROM addresses are private import and round-trip
verification inputs only. After that verification, a conforming remake runtime may use engine-native
references and is not required to reproduce the Mega Drive address space, big-endian pointer
storage, or the original in-memory table layout. This implementation freedom does not weaken the
private fidelity requirements above or permit loss of the evidence needed to verify them.

The ten compact selection cases are not H4 requirements for this data contract. Selector fidelity is
accepted through the existing map-exploration owner. H4 may use synthetic route graphs for importer
tests, but public tests MUST NOT reproduce the private original graph.
