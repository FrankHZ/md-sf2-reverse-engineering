# Map 3 受控准入合同

Canonical source: [English](../../contracts/map3-controlled-admission.md). 英文为规范审阅基线；本译文遵循[术语表](../../glossary.md)。

- 状态：**提议（Proposed）**
- 证据日期：2026-08-20
- 范围：以实现中立的方式，将已接受的受控 Map 3 起始状态准入至第一个探索边界；不要求产品执行原版 Witch/New 生命周期，不虚构自然路线，也不启动 Phase 4 实现

## 当前适用性

本**提议**合同保留其证据日期及有界 R1 测试夹具投影。它不是当前里程碑就绪台账。[连续场景合同](../../contracts/map3-battle01-continuous-scenario.md)拥有后续路线和比较要求，[就绪台账](../../synthesis/map3-battle01-readiness.md#accepted-current-milestone)拥有在组合 8D/H4 边界上已接受的当前私有里程碑。[ADR 0010](../../../decisions/0010-map3-battle01-product-acceptance.md#current-acceptance-amendment)及其[现代时钟修订](../../../decisions/0010-map3-battle01-product-acceptance.md#accepted-modern-finite-music-clock)控制当前保真度和时钟适用性；[ADR 0019](../../../decisions/0019-state-and-content-driven-remake-engine.md)拥有已采用的引擎方向和实现边界。下文有关未来实现/H4 和 Phase 4 启动的措辞描述的是本地提案，不是当前实现状态。

后续验收不会扩大本测试夹具投影、提升本合同状态，或解决其原有未知项。尤其是，原始受控 R1 测试夹具的金币 0/四字节物品投影，与后来连贯路线中选定 R1 的修正仍须区分；后者改为金币 60 及完整起始物品字，其结果和限制归[连续场景比较记录](../../contracts/map3-battle01-continuous-scenario.md#remaining-acceptance-work)所有。历史失败和报告结论保持不变。

## 判断边界

本合同始于 `sf2-map3-admitted-start-runtime-v1` 记录的已接受受控结果；终于已验证的产品场景构造出精确的已接受逻辑准入投影及配置/初始化结果，并准备准入第一个探索行动之时。它不拥有进入 Map 3 的自然路线，也不拥有该边界之后的任何行为。

- **已确认受控证据**：一个原版运行时用例按照测试夹具记录的受控 Witch/New、新游戏、存档服务、主循环、探索循环、配置选择和选定初始化时序，到达原版第一个 `WaitForEvent`。到达的结果包含完整的有界非时间场景状态、保持源码形态的主循环交接、选定默认配置/初始化结果、一个已观察 RNG 状态，以及边界之前没有受守卫控制的程序请求这一结果。
- **已接受产品方向**：ADR 0010 选项 1A 允许重制版直接构造该已接受结果。产品准入要求第一个探索边界上的结果等价；不要求调用、程序计数器、菜单、命名、存档服务或时序等价。
- **未知**（本地 R1 证据接缝未确立）：自然、玩家可见的 New 或读档流程；原版原始时间计数器值；其他自然或受控起始是否具有相同 RNG 状态；自然 Map 3 移动、对话、菜单、事件、切换或战斗准入；所有后续战斗及端点行为；完整呈现、音频、时序与硬件观察；以及存档持久化。

这些是本接缝的证据限制，不是当前产品缺口清单；后续已接受所有者保留各自的证据和验收边界。

已接受测试夹具仍是黄金标准。本文件只命名有界字段类别与比较规则，不把其中的值复制成第二个、更弱的事实来源。

## 原版证据与产品准入

原版受控时序与产品准入路径承担不同义务：

| 表面 | 必需含义 | 明确不作的声明 |
| --- | --- | --- |
| 原版证据回执 | 保留并比较测试夹具拥有的完整 H3 闭包，包括保持源码形态的交接、原始 D0-D4 值、PC、地址、回调身份、时序、溯源、边界及规范化能力 | 不使这些证据字段成为产品权威状态，也不要求重制版执行原版路线 |
| 产品准入结果 | 标识已验证场景/包，并证明精确的已接受逻辑地图/起始位置/朝向/流程、军团/会话、配置/初始化、无程序请求及探索就绪投影 | 不存储或合成 D0-D4、PC、RAM/ROM 地址、回调身份或原版生命周期执行 |

`OriginalEvidenceReceipt` 与 `ProductAdmissionResult` 是这两个表面的未来设计标签。它们不是测试夹具 ID、可执行 schema、C# 类型，也不新建 Research 数据所有权。未来实现可使用不同名称，但须保留此分离。

当已接受的相邻所有者确立某个寄存器形态观察的语义结果时，产品投影应将该结果映射到已命名逻辑字段。**不得**保留重复的寄存器形态产品字段。没有已接受语义映射的原始交接字段仍仅属于证据。

H4 报告**必须**使两种结果均保持可见。产品准入成功不能覆盖或重标原版证据回执；原版 H3 成功也不能证明产品包已通过验证或准入。

## 已接受证据与产品投影

本合同在测试夹具证据上定义两个比较投影。`OriginalEvidenceReceipt` **必须**在原版 H3 一侧保留并比较完整的源码形态闭包。`ProductAdmissionResult` **必须**仅验证其含义已由已接受所有者确立的精确逻辑准入投影。后者包含以下产品类别：

| 类别 | 原版证据表面 | 产品准入义务 |
| --- | --- | --- |
| 地图交接 | 当前/退出地图，以及完整源码形态主循环交接，包括原始寄存器事实 | 仅验证已接受逻辑地图、起始位置、朝向和流程状态字段；未映射原始交接事实仍仅为证据 |
| 玩家与会话状态 | 玩家实体状态、金币及难度状态 | 通过类型化状态保留精确准入值及已接受字段宽度/范围 |
| 军团状态 | 每个已加入/出战事实，以及完整已接受伙伴记录字段 | 构造完整有界军团快照；省略或以默认值填充记录都会导致准入失败 |
| 配置/初始化结果 | 选定默认配置身份、选定初始化身份、分发返回接缝，以及在首次探索等待前完成 | 验证选定逻辑配置/初始化 ID，并证明其准入结果完整 |
| 受守卫控制的程序结果 | 已接受的边界之前没有受守卫控制的程序请求这一事实 | 暴露相同有界结果；缺失能力不等价于已接受的无请求结果 |
| 探索就绪 | 到达原版首次探索等待 | 仅在前述所有结果检查通过后，才准入第一个语义探索行动 |

原版寄存器名称和值、RAM/ROM 地址、源码符号、回调身份及 PC 属于完整证据回执和导入器溯源。它们**不得**成为权威玩法状态，也不得泄漏到纯领域模型。产品映射使用引擎中立逻辑 ID 与类型化值，**必须**完整覆盖已接受逻辑投影、带有版本，并可按照测试夹具拥有的类别诊断。产品成功**不得**要求有意排除的原始证据字段。

每个投影内部采用精确相等：原版证据回执比较测试夹具拥有的完整闭包，产品准入比较完整已接受逻辑投影。产品结果等价不要求重制版运行原版配置代码、选定初始化代码或原版主循环/探索循环。未来产品可以构造已解析快照，也可以执行独立维护的类型化程序，只要该边界上的逻辑准入结果和能力报告保持相同。

## 时间与 RNG 分离

测试夹具记录 4 个不同状态区间：1 个 RNG 区间和 3 个由原版 VInt 维护的时间区间。它们不共用一条规范化规则。

### 原版原始时间

观察器在原版首次 `WaitForEvent` 处，以忠于源码的宽度读取每个原始时间计数器。已接受测试夹具不将这些原始值发布为稳定期望。因此它们属于**未知/未发布**，不参与原版状态相等比较，也不能作为产品时钟默认值。

### 边界之后的测试台规范化

R1 观察器仅在原版 `WaitForEvent` 之后、所有回调之外，规范化这 3 个时间区间并验证恢复。测试夹具标签 `post-boundary-controlled-zeroed-vint-counters` 标识该测试台变换。

声称复现 R1 配置的原版证据回执**必须**报告此规范化能力及标签，**不得**将规范化值描述为原版快照事实。产品准入结果**不得**仅因证据测试台使用此变换就继承零值时钟。

### 产品时钟所有权

产品确定性时钟是 ADR 0011 下独立的 Application/H4 输入。当前政策由 [ADR 0010 的已接受现代时钟](../../../decisions/0010-map3-battle01-product-acceptance.md#accepted-modern-finite-music-clock)拥有，比较适用性见[连续场景合同](../../contracts/map3-battle01-continuous-scenario.md#modern-clock-applicability)。本地 R1 接缝不确立原版纪元、第一步或与后续时序证据的映射；它不准入原版时间相等比较，也不选择任何产品时钟值。其未发布原版计数器及边界后规范化，不会把已接受产品时钟重新变成未来工作。

### 受控 RNG 观察

RNG 区间在边界后时间规范化之前观察，不受该规范化变换。其精确测试夹具值仅作为这一个受控用例的状态准入。**不得**将其泛化为通用自然新游戏种子、所有起始状态规则，或使用隐藏/时间派生随机流的许可。H4 可以精确比较该受控用例，其他起始及后续到达的 RNG 调用序列仍各归其所有者。

## 导入与准入规则

本接缝的未来场景包**必须**在玩法会话存在之前通过准入。准入边界至少要求：

- 已接受测试夹具/场景身份及内容摘要；
- 受支持的合同与包版本；
- 上文列出的完整已接受逻辑产品投影；
- 按适用范围验证逻辑地图、配置、初始化、行动者、职业、物品和法术引用；
- 显式溯源类别及必需能力；
- 分离的原版证据与产品准入结果字段；
- 显式确定性时钟能力，不虚构原版时间值；
- 仅限该用例的受控 RNG 字段；
- 不把任何不支持或未解决字段悄悄替换为默认值。

缺失字段、摘要不匹配、不支持版本、重复或未解析逻辑 ID、不完整军团记录、错误配置/初始化结果、意外程序请求、不支持溯源/能力或有歧义的证据到产品映射，均须拒绝准入。诊断须标识场景阶段、字段/类别、预期测试夹具所有者、实际结果及负责边界。

私有 7C 配置只能通过已验证身份与溯源的忽略本地输入解析原版证据。公共合成配置可用可安全再分发的项目自创数据，演练相同包及准入形态，但不作原版状态、原版资产、7C 或 8C 声明。两种配置均不授权公开发布。

## H4 验收表面

未来 H4 适配器只有满足以下条件，才通过本提议合同：

1. 针对已接受 R1 测试夹具身份验证一个具名原版证据回执，包括受控时序、私有溯源、观察边界及边界后规范化标签；原版运行时复现仍由 H3 所有者负责；
2. 通过普通验证路径准入产品包，不调用或声称执行原版 Witch/New、新游戏、存档服务或主循环时序；
3. 在原版证据回执中比较测试夹具拥有的完整源码形态闭包，包括原始交接寄存器、PC、地址及回调身份，且仅在该侧比较这些内容；
4. 比较精确已接受逻辑产品投影，不要求 D0-D4、PC、RAM/ROM 地址、回调身份或重复寄存器形态产品字段；
5. 证明选定配置/初始化结果、无程序请求结果及首次探索就绪，不把源码地址或回调 PC 当作领域状态；
6. 保持原版原始时间为**未知/未发布**，测试台规范化时间仅作证据，产品确定性时钟状态另行标记；
7. 仅对该受控用例比较测试夹具 RNG 状态，并拒绝意外 RNG 字段或隐藏随机源；
8. 独立报告原版证据与产品准入失败，不将回退计为精确成功；
9. 保持测试夹具为黄金标准，不将选定值复制成引擎专用快照；
10. 不声称已到达全部 26 条 Map 3 汇总记录、替代配置行或后续路线事件；
11. 将完整 8C 像素、调色板、帧节奏、动画、音频、VInt/DMA/CRAM/VDP 观察、顺序、时序及容差排除在本地准入合同之外。

这些检查只定义未来观察接缝，不构成 H4 实现或 Phase 4 启动。

## 阶段与分发边界

本提议合同不使就绪台账变为就绪，不授权 `remake/`，不启动 Phase 4，不选择 MCP 工作流，不运行 Godot，不定义引擎场景，也不改变产品代码。它不授权发布 ROM、SRAM、轨迹、采集、提取资产或其他私有输入。Godot 和未来组合根仍是已接受 Application 准入结果的外层使用方。

后续任何连续 Map 3 至 Battle 01 场景合同都必须将本地准入接缝作为一个有界所有者消费。不得削弱其黄金标准、悄悄替换测试夹具，或将其用作 R2、R3、R4 或完整 8C 闭合的证明。

## 复现

已接受受控证据及未变化的关系计数可通过以下命令复现：

```powershell
uv run sf2 h3 map3-admitted-start
uv run sf2 design-contracts test
uv run sf2 research-index test
uv run sf2 verify
```

这些命令验证已接受证据和仓库关系；不执行重制版、不证明自然路线，也不授权 Phase 4。
