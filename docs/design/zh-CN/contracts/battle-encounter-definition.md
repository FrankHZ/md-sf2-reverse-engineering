## 合同边界

本合同定义已接受原版数据如何把战术遭遇划分为稳定身份与配置域。它拥有：

1. 45 个源码形式 spriteset 与地形条目的战斗槽身份；
2. 己方放置、敌人放置、AI 区域与 AI 点的结构形状；
3. 战斗索引地图坐标、触发覆盖、背景、敌人队长标志与其他受限全局元数据；
4. 地形载荷选择及其两个已确认别名；
5. 战斗过场路由使用独立 48 槽命名空间的事实。

它不拥有战斗员运行时生命周期、AI 决定、玩家动作构建、寻路、伤害或 EXP 公式、战斗演出呈现、故事推进或过场执行。那些仍属于相邻合同、研究所有者或 **未知**。

  [`tests/fixtures/h2/battle-spriteset-data-static-v1.json`](../../../../tests/fixtures/h2/battle-spriteset-data-static-v1.json)；
- `sf2-battle-global-data-static-v1`，位于
  [`tests/fixtures/h2/battle-global-data-static-v1.json`](../../../../tests/fixtures/h2/battle-global-data-static-v1.json)；
- `sf2-battle-routing-data-static-v1`，位于
  [`tests/fixtures/h2/battle-routing-data-static-v1.json`](../../../../tests/fixtures/h2/battle-routing-data-static-v1.json)。

研究所有者是[battle spriteset data](../../../research/battle-spriteset-data.md)、[global battle data](../../../research/battle-global-data.md)与[battle routing 与 terrain data](../../../research/battle-routing-data.md)。

## 合同前证据审计

本综合对照三个研究所有者、其受追踪测试夹具与其 H2 验证器检查。审计保留四个重要限制：

- spriteset 与 global-data 测试夹具保留计数、地址、hash、所选索引与结构预期，而非再分发源行；
- 完整规范行只在忽略的 `local/derived/` 输出下从合法私有研究输入生成；
- Battle 01 有更深的放置/运行时所有者，不得泛化到全部 45 场战斗；
- routing 所有者闭合地形指针选择、别名与解压，但不闭合过场准入或故事状态含义。

因此受追踪证据对实现无关形状与连接合同是充分的。它对公开仓库中的完整遭遇数据库，或对每个字段运行时含义已闭合的主张，是不充分的。

## 身份域

实现必须保持以下身份分离：

| 域 | 已确认原版边界 |
| --- | --- |
| 战斗槽 | 源码形式 spriteset 表与地形表的索引 0 到 44 |
| spriteset 载荷 | `BattleSpriteset00` 到 `BattleSpriteset44`，每槽一个源文件 |
| 地形载荷 | 由 45 个战斗槽选择的 43 个唯一压缩载荷 |
| 过场路由槽 | 四个独立 48 槽相对指针表中的索引 |
| 地图身份 | 45 行七字段战斗地图行引用的 33 个不同地图 |
| 战斗员放置 | 一个所选 spriteset 内的源码宏记录，不是全局名册槽 |
| AI 区域与点 | 一个所选 spriteset 内的源码几何/目标记录 |

48 个过场路由槽不得被截断、位置连接或描述为与 45 个战斗槽相同的命名空间，除非有新调用方证据。同样，地图身份不是战斗身份：多个战斗行可以引用同一地图。

## 四十五槽遭遇主干

已接受源码清单在这些配置面上建立公共 45 条目主干：

| 面 | 已确认形状 | 合同用途 |
| --- | --- | --- |
| spriteset 条目 | 45 个有序 longword，`BattleSpriteset00` 到 `BattleSpriteset44` | 选择放置与局部 AI 几何载荷 |
| 战斗地图行 | 45 行、每行七字段、33 个不同地图身份 | 选择地图坐标与受限触发元数据 |
| 自定义背景 | 45 个战斗级条目、24 个不同值 | 保留原版所选值 |
| 敌人队长标志 | 45 个条目、28 个标记在场 | 把成员保留为遭遇元数据 |
| 地形条目 | 45 个指向 43 个唯一载荷的指针 | 选择初始地形网格载荷 |

该对齐允许重制导入器暴露一个战斗索引遭遇记录，带对独立拥有载荷的类型化引用。它不证明每张表同时被读取、一个故事路线一起选择所有字段，或每个字段影响每场遭遇。

## Spriteset 结构形状

跨 45 个 spriteset 头，已确认源码总计：

| 记录种类 | 总计 | 逐战斗范围 |
| --- | ---: | ---: |
| 己方放置 | 500 | 3-13 |
| 敌人放置 | 627 | 6-20 |
| AI 区域 | 133 | 0-14 |
| AI 点 | 37 | 0-2 |

解析器独立计数 500 个 `allyCombatant` 宏、627 个 `enemyCombatant` 宏，以及各 1,127 个 `combatantAiAndItem` 与 `combatantBehavior`，拒绝头计数与宏体之间的分歧。

这些数字描述源码记录。它们不得被重新解读为：

- 玩家的名册选择容量；
- 运行时控制器同时存活或被准入的战斗员数量；
- 每个源码放置立即可见的证明；
- 特定 AI 策略、物品效果、跟随目标过渡或区域激活规则的证明。

运行时战斗员准入与清理归[battle-control 合同](../../contracts/battle-control-lifecycle.md)。AI 解读归[battle-AI 决定合同](../../contracts/battle-ai-decision.md)，玩家发出命令归[battle-action 构建合同](../../contracts/battle-action-construction.md)。已接受受限运行时用例之外的隐藏/延迟生成状态保持 **未知**。

## 地图坐标与触发元数据

全局所有者确认 33 张地图上的 45 行七字段战斗地图行。战斗索引 11、25 与 41 有非默认触发坐标。保真导入器必须保留：

- 战斗索引；
- 全部七个源码派生字段及其规范顺序与类型；
- 地图身份与战斗身份之间的区分；
- 显式默认对非默认触发表示。

触发行建立存储遭遇元数据，而非调用方准入测试、正常剧情可达性、碰撞行为、摄像机放置或过渡何时可见。地图移动与碰撞仍归[地图探索合同](../../contracts/map-exploration.md)；战役选择在本合同之外。

## 地形选择边界

地形指针表有 45 个战斗槽，由 43 个唯一压缩载荷支撑。两个别名已确认：

- 战斗槽 4 复用地形载荷 3；
- 战斗槽 32 复用地形载荷 27。

`LoadBattleTerrainData` 用 `CURRENT_BATTLE * 4` 索引指针表、写入固定战斗地形数组并调用已接受 Stack 解码器。每个唯一载荷产生一个 2,304 字节的 48×48 网格。

本合同只拥有所选载荷身份与别名保留。地形值、移动消耗、阻挡、邻接、可达性、路线构建与光标交互归[战场导航合同](../../contracts/battlefield-navigation.md)。实现必须把别名保留为等价所选内容；它可以在内部去重存储。

## 背景、队长与成员元数据

全局表还建立这些受限战斗索引或类别索引事实：

| 表 | 已确认静态形状 | 语义边界 |
| --- | --- | --- |
| 自定义战斗背景 | 45 个条目、24 个不同值 | 所选值已确认；可见组合/时序独立 |
| 敌人背景开关 | 30 个标志；索引 3、11、18 与 27 启用 | 成员已确认；可见朝向 **未知** |
| 地形背景 | 16 个条目、7 个不同值 | 映射形状已确认；渲染独立 |
| 敌人队长 | 45 个标志、28 个在场 | 成员已确认；败北/结果使用归 battle control |
| 减半 EXP 成员 | 一个战斗条目 | 成员已确认；EXP 算术归交战解决 |

战斗背景与开关不定义战斗演出排序、调色板时序或资源转移。那些仍归[battle-scene presentation 合同](../../contracts/battle-scene-presentation.md)。减半 EXP 行不得被用作计算或奖励时序的独立证明；那些归[交战解决合同](../../contracts/combat-resolution.md)。

## 移动矩阵边界

global-data 所有者确认一个包含 208 个条目（其中 127 个被阻挡）的 13×16 地形效果/移动消耗矩阵。本合同把该矩阵保留为被引用的遭遇支持域，而非遭遇编写行内容。

移动类含义、消耗查找、阻挡、占用、可达性、路径平局打破与地图维度归[战场导航](../../contracts/battlefield-navigation.md)。除非后续设计决定显式创建带单一真相来源的派生编写视图，否则遭遇工具不得把该矩阵复制成独立可编辑平衡表。

## 中立、激光、随机与特殊元数据

已接受全局清单确认以下额外形状：

- 11 场战斗包含使用四个实体动作脚本的 17 个中立实体；
- 三场激光战斗携带逐敌人朝向行，分别为 24、16 与 12 个条目，各有 8、2 与 2 个激活激光朝向；
- 11 场战斗在随机战斗表中；
- 敌人升级使用五个类别，包括一个刻意为空的空中排除列表；
- 一个战后位置表包含三个四字节实体放置。

这些是表与成员事实。中立动作时序/呈现、激光控制与视觉效果、随机战斗准入、升级边界与失败行为、战后行选择与源码标记忽略的第四位置字节不由本合同闭合。导入器必须保留缺席、空与已填充类别之间的源码区分；模拟器必须使用更深所有者或保持行为 **未知**。

## 过场与战后路由边界

四个独立相对指针表各包含 48 个槽：

| 路由表 | 非空目标 |
| --- | ---: |
| 战前 | 27 |
| 开战 | 1 |
| 败敌 | 3 |
| 战后 | 25 |

路由清单还确认四个区域路由后接终止符，以及一个 52 字节源码标记未使用的战后加入表，其每个字节为零。

合同保留表身份、槽计数、空与非空状态，以及未使用 alternate 从活动布局所有权中的排除。它不声称：

- 48 个路由槽与 45 个战斗槽之间的位置等价；
- 过场准入、空槽回退、可重复性或标志生命周期；
- 叙事含义、呈现顺序、渲染效果或存档持久性；
- 未使用全零战后加入表的活跃使用。

那些行为在专用调用方/运行时所有者闭合它们之前保持 **推断** 或 **未知**。

## Alternate 与遗留数据

顶层 `spritesetentries.asm` 是定义与维护的源码形式 spriteset 树相同符号的 45 载荷二进制聚合，但原版布局不 include 它。它是显式 hash 的 alternate，不是规范可编辑源，也不是额外遭遇集。

同样，`data/battles/global/afterbattlejoins.asm` 是未使用 52 字节全零 alternate；layout 拥有的表在 `data/battles/cutscenes` 下。重制导入器不得双计数任一 alternate，也不得给它借用运行时可达性。

## 保真与现代化边界

原版保真遭遇定义必须保留：

- 独立的战斗、地图、地形载荷与过场路由身份；
- 全部 45 槽结构连接，而不发明第 46 场战斗；
- spriteset 头计数与源码记录顺序；
- 地形别名 4→3 与 32→27；
- 空、缺席、禁用与已填充元数据作为不同状态；
- 48 槽过场表形状，而不强迫它们进入 45 槽战斗命名空间；
- 排除的 alternate 文件作为溯源，而非活跃遭遇内容。

未来重制可以把记录规范化为类型化对象、去重别名载荷、暴露遭遇编辑器、添加验证预览或刻意重平衡遭遇。它也可以在原版 45 场之外创建新战斗。那些是产品决定，必须表示为新或覆盖内容，绝不静默报告为原版事实。

## H4 验收面

未来 H4 适配器应验证规范导入状态，而非原版源语法或 RAM 地址。对每次合法局部提取，它应比较：

1. 45 个有序遭遇身份及其 spriteset、地图行、背景、队长与地形引用；
2. 逐 spriteset 头计数与聚合总计/范围；
3. 别名 4→3 与 32→27 的地形所选内容相等性；
4. 受限全局表的维度与成员索引；
5. 四个独立 48 槽过场路由在场向量；
6. 遗留 spriteset 聚合与未使用全局战后加入 alternate 的排除。

公开受追踪测试夹具可以验证计数、hash、地址与所选索引。精确逐行 H4 一致性需要从合法私有输入生成的规范输出，不得通过从聚合 fixture 事实发明行来近似。

遭遇通关、战术选择、生成演化、路线准入、故事过渡、渲染与平衡在其专用证据或设计决定存在之前保持在该适配器之外。
