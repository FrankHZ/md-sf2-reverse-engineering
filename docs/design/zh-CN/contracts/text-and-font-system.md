## 合同边界

本合同定义从原版文本行 ID 经其压缩记录与上下文解码器到字形 ID 流与字体元数据的导入与身份边界。它拥有：

1. 原版全局行 ID、库、记录、压缩载荷与指针表形状；
2. context-Huffman 偏移、树打包、码、可达性与解码器状态事实；
3. 不发布明文的所有原版压缩记录确定性聚合回放；
4. ASCII 字节到字形映射与可变宽度字形记录元数据；
5. 基于结构、计数、地址与 hash 而非版权文本或字体像素的公开 H4 面。

它不拥有 map-script 对话命令路由、立绘或语音 SFX 选择、控制码执行、名称/物品/法术替换、窗口、字形光栅组合、输入等待、音频、战役顺序、翻译或最终呈现。相邻[dialogue-command 合同](../../contracts/dialogue-system.md) 拥有源命令布局与处理器局部游标接缝；它刻意不解码或渲染本语料。

本综合对照三个专用 fixture、其验证器、生成静态输出、解码器与显示源片段、全部库载荷、Huffman 树载荷与字体/ASCII 资源检查。证据日期三个专用所有者新鲜复现全部通过。审计保留以下限制：

- 受追踪文本库 fixture 不包含明文；解码逐字符串符号数组保留在忽略的本地根下，`gamescript.txt` 只贡献其计数、ID 连续性与 hash；
- 压缩长度前缀限定存储字节，而解码器在符号 254 停止；观察到的 8 到 15 尾存储位作为数据事实保留，不标记为填充或内容；
- 符号 238 到 253 的源标签不建立控制码效果、操作数宽度、等待、替换、调色板变更或可见含义；
- 符号 253 缺席全部 4,267 条原版记录，证明语料缺席而非直接或修改输入下的不可能；
- 字形 ID 70 与 71 缺席两个已接受普通输入路径，未被证明从每个调试、直接、修改或损坏调用方不可达；
- 源调用计数区分普通与非普通对话路径，但不建立像素、重叠、时序或玩家可见布局；
- 当前失败的聚合 `sf2-tech-interfaces-static-v1` 轨道不是证据依赖。其对 `InitializeHuffmanDecoder` 的跳转表记录被排除；专用 Huffman fixture 拥有此处使用的解码器地址与源形状事实。本文档不声称新鲜 tech-interfaces PASS。

三个专用所有者中没有发现矛盾。一个已接受上游注释说 Huffman 偏移表有 256 个条目；实际 510 字节载荷包含 255 个，可执行所有者刻意保留该不匹配而非重复注释。

## 身份域

实现必须保持以下身份分离：

| 域 | 已确认原版边界 |
| --- | --- |
| 全局文本行 ID | 连续源域 0 到 4,266 中的一个整数 |
| 库索引 | 行 ID 的高部分 `lineId >> 8`，选择 17 个库之一 |
| 库内索引 | `lineId & 255`；有效行由所选库的实际计数决定 |
| 存储记录 | 一个长度字节后接那么多压缩字节 |
| 压缩位位置 | 存储载荷内的状态；终止可能留下 8 到 15 个存储位 |
| 解码符号 | 由上一符号的 Huffman 树选择的一个字节 |
| 上下文符号 | 上一解码符号；初始值为 254 |
| 控制符号 | 238 到 254 的解码符号；身份闭合，效果不闭合 |
| 字形 ID | 一基字体记录 ID 1 到 80 |
| ASCII 字节 | 经 256 条目表映射后在字形使用前的备用直接输入字节 |
| 源文本 | 保持受追踪 fixture 与公开输出之外的版权玩家面向内容 |
| 本地化文本 | 独立编写产品内容；绝不从原版符号 ID 推断 |

规范导入必须保留全局行 ID，即使重制把文本存储在具名资源中。库位置、压缩字节、解码符号、字形 ID 与本地化字符串相关但不得折叠成一个可互换标识符。

## Context-Huffman 树合同

**已确认静态：** 偏移资源为 510 字节，给出 255 个大端条目。86 个条目选择树，169 个包含 `0xFFFF`。定义偏移唯一且严格递增。1,952 字节树资源连续打包全部 86 条记录，无空隙或重叠。

每条记录先按逆序存储其叶符号，再存节点位流。跨全部记录：

| 事实 | 已确认值 |
| --- | ---: |
| 叶条目 | 1,536 |
| 非叶节点 | 1,450 |
| 节点位 | 2,986 |
| 节点存储字节 | 416 |
| 符号存储字节 | 1,536 |
| 零填充位 | 342 |
| 码长范围 | 0..14 位 |
| 每树叶数范围 | 1..66 |

节点位 `0` 打开左右子节点；位 `1` 选择叶。输入位 `0` 走左分支，`1` 走右分支。上下文 54 是唯一单叶树，不消费输入位即发出符号 58。

**已确认图边界：** 所有树发出符号集恰好等于 86 个定义上下文符号集。从初始上一符号 254 开始，每个定义上下文可达，没有已接受解码路径需要 169 个缺失条目之一。这闭合静态上下文图，而非任何发出符号的语义含义。

原版格式解码器必须保留上一符号上下文、跨调用位桶、分支顺序、逆序叶存储与零位单叶用例。现代文本管线可以把已接受私有输入转码为不同表示，前提是导入适配器能复现规范符号 hash 与边界。

## 文本库与记录合同

**已确认静态：** 十六个库各包含 256 条记录，库 16 包含 171 条，共 4,267 条记录。17 个库载荷占用 79,013 字节：

| 组件 | 已确认字节/计数 |
| --- | ---: |
| 长度前缀 | 4,267 字节 |
| 压缩载荷 | 74,746 字节 |
| 库载荷总计 | 79,013 字节 |
| 17 条目指针表 | 68 字节 |
| 最终库与指针表之间的对齐 | 1 字节 |
| 顶层指针 | 4 字节 |
| 总 source/ROM parity 边界 | 79,086 字节 |

源选择公式是 `bank = lineId >> 8` 与 `withinBank = lineId & 255`。库内，所选记录通过为每个先前记录推进 `1 + lengthByte` 到达。这是导入/布局规则，不是读取部分库中实际 171 行之外的许可。

完整确定性回放产生 152,679 个解码符号，其中 4,267 个是每条记录的单一终止符 254，148,412 个是非终止符。全部 86 个定义上下文都出现。存储压缩载荷长度范围 3 到 116 字节，而含单字节前缀的完整存储记录大小范围 4 到 117 字节。解码记录长度范围 2 到 243 个符号，终止符在每条记录留下 8 到 15 个存储位。

相邻源脚本恰好有连续 ID 0 到 4,266。其明文与逐记录解码符号序列保持私有/生成；受追踪证据只保留聚合事实与 hash。重制导入器可以验证用户提供的私有源包，而不使该包成为仓库或分发依赖。

## 符号与控制边界

解码器从上一符号 254 开始、从上一解码符号选择树、发出一个新符号并让该符号成为下一上下文。符号 254 终止当前记录。符号 238 到 252 在原版语料中于终止符前出现 8,783 次。符号 253 出现零次。

这些只是字节域事实。在专用所有者闭合每个消费者前，重制必须把控制符号与任何后续字节保留为源忠实结构化输入，而非指定猜测操作。特别是，本合同不定义：

- 每个控制符号的参数宽度或游标推进；
- 名称、物品、法术、数字或其他替换；
- 窗口开/关、换行、等待、输入准入或跳过行为；
- 字体颜色、调色板、立绘、语音 SFX 或其他呈现效果；
- 符号 253 是否可以通过非标准输入到达。

现代标记与本地化 token 是刻意编写选择。其适配器必须在保真测试或原版内容导入需要该可追溯性时保持回已接受原版 ID 的显式映射。

## 可变宽度字体合同

**已确认静态：** 字体载荷为 2,560 字节，包含 80 个固定 32 字节字形记录。每条记录有填充宽度头后接十五个双字节行，带十二个可用像素列。所有头与行填充位为零。已接受元数据包含一个空白字形、1,633 个设置像素、746 个带像素的行、存储宽度 3 到 9，以及五个设置像素延伸至或超过计算推进的字形。

源加载器使用一基 ID：减一、左移五、把结果加到字体基址。它把存储宽度掩蔽到低半字节、存储值零时推进零，否则推进 `storedWidth + 1`。没有受追踪 fixture 导出字形像素。整字体、指针与 ASCII 映射 hash 加聚合形状计数器提供受追踪公开 parity 面；逐字形 hash 保持生成局部元数据。

256 条目 ASCII 映射只接受字形 ID 1 到 80。它到达 78 个唯一 ID、把 145 个输入字节映射到默认字形 1、有 79 个非默认可打印 ASCII 条目与 32 个非默认扩展字节条目，且从不发出字形 ID 70 或 71。Huffman 语料独立在字形范围发出 69 个 ID；两个普通输入并集仍到达 78/80 并省略同一两个 ID。

**已确认源拓扑：** `GetNextTextSymbol` 只在源具名 RAM ASCII 指针非零时使用 ASCII 表；Huffman 路径绕过它。`SymbolsToGraphics` 对普通对话调用一次字形加载器，在源非普通路径调用两次。渲染重叠、调色板、推进组合、DMA 与时序保持 **未知**。

## 调用方与相邻系统边界

[dialogue-command 合同](../../contracts/dialogue-system.md) 对照连续 0 到 4,266 域验证行 ID 操作数，并拥有命令/游标排序。本合同拥有有效行 ID 如何选择存储文本以及解码符号如何与字体身份相关。两个合同单独都不证明端到端玩家可见对话。

窗口构建、立绘放置、说话声、控制器等待、map-script 可达性、故事顺序与存档持久性仍归各自所有者。调用方可以只保留行 ID，而文本系统可以向后续服务返回不透明符号/控制流。该接缝优于把窗口或故事行为嵌入解码器。

## 保真、本地化与版权边界

原版格式兼容要求保留：

- 全局 ID、库与库内选择、记录边界、指针与 source/ROM hash；
- 精确上下文树图、解码器状态、位顺序、叶顺序与终止符行为；
- 无猜测效果的解码符号/控制身份；
- 字形 ID、ASCII 映射、记录宽度、填充有效性与加载器地址/推进公式。

现代重制可以刻意选择 UTF-8 文本、成形字体、比例布局、可缩放 UI、从右到左支持、可访问性设置、新控制标记与独立本地化。那些选择不改变原版证据。映射层应报告现代内容或行为在哪刻意偏离原版 ID/符号合同。

原版明文、压缩库字节、解码符号序列、字体像素、截图与捕获渲染保持私有/生成版权输入。不要提交或再分发它们。只有单独许可或新编写文本与字体可以随公开重制发布。

## H4 验收面

重制侧导入器或兼容适配器只在自动化测试证明以下内容时声称本合同：

1. 恰好 4,267 个原版行 ID 映射到已接受 17 库、16 满/一部的记录形状；
2. 指针顺序、压缩载荷长度、派生存储记录长度、库载荷 hash、聚合解码 hash、终止符计数与 source/ROM parity 元数据匹配已接受私有输入；
3. 全部 255 个偏移条目、86 棵树、1,536 个叶、打包跨度、码长与上下文图可达性匹配规范所有者；
4. 解码从上下文 254 开始、保留跨调用位/上下文状态、处理零位叶、每条记录发出一个终止符；
5. 控制符号保持无损不透明身份，直到独立已接受行为所有者定义其效果；
6. 全部 80 个字形记录与 256 个 ASCII 映射保留 ID、宽度、填充有效性、缺失 ID、加载器公式与已接受整字体/指针/ASCII 映射 hash；

8. 本地化或现代化文本/渲染行为与原版存储/解码器/字体 parity 分别测试与报告。

H4 不要求原版 Huffman 格式或位图字体作为重制编写/运行时格式。它要求使用原版兼容私有数据时确定性保留溯源的导入。
