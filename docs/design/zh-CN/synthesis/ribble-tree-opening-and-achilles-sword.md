# Ribble 树洞开启与 Achilles Sword

已接受的物品内容支持这样一个谜题：取得 Wooden Panel，在 Ribble 面朝树使用它，随后搜索另一处神殿宝箱以取得 Achilles Sword。开启程序先请求跳跃、向下移动、震动及三次图块替换，再标记树已开启并尝试移除一块 Panel。此后，Sword 的持有状态可以满足 Hassan 中 Rohde 的首次持有检查。

**推断：**这是预期的 Panel／树／Sword 关联。**已确认：**下文选定的宝箱、物品使用、场景、物品栏和地图请求规则来自已接受的[研究所有者](../../../research/ribble-tree-opening-and-achilles-sword.md)。**未知：**自然接近、在共用神殿地图内行走、场景／服务实际完成、开启画面的渲染、连续持有、可用控制以及存档／恢复持久性。本指南是有条件的玩法内容说明，不规定它与编号战斗或 Hassan 对话之间的必经顺序。

Fnnn 表示标志 nnn；坐标单位为地图瓦片；记录索引从零开始。Map8 为 Ribble，Map50 为 `MAP_ACHILLES_SHRINES`，Map61 则是独立的 `MAP_RIBBLE_SHRINE_EXTERIOR`。共用 Map50 身份并不能证明其不同区域之间存在步行路径。城镇配置见 [Ribble 的欢迎（英文）](../../synthesis/battle09-outcomes-through-ribble-welcome.md)，后续持有检查调用方见 [Hassan 的 Rohde 选择（英文）](../../synthesis/hassan-ancestry-and-rohde-caravan-choice.md#talking-to-rohde)。两者都不是此处新增的前置条件。

## 两个宝箱，两次独立的持有判定

**已确认的选定内容：**Map50 宝箱表包含以下记录。它们都不检查 F731、是否持有另一件物品、Rohde 的标志、出战队伍成员资格或战斗完成状态。

| 物理记录行 | 搜索候选位置 | 标志未设置时提供的物品 | 宝箱标志 |
| --- | --- | --- | --- |
| 1 | `(14,2)` | Wooden Panel `$70` | F152 |
| 2 | `(35,6)` | Achilles Sword `$3D` | F147 |

这些坐标标识宝箱候选位置，并不表示站上去便会取得物品。FieldMenu Search 调用 `CheckArea` 并退出主菜单。普通 C 交互先等待物理实体 0 和滚动，随后可以选择附近的行动者；只有未选中行动者的分支才搜索区域。对于普通视野目标 0，搜索计算一个**按朝向偏移的瓦片**，在工作布局中检查宝箱属性 `$1800`（掩码 `$3C00`），并查找坐标完全匹配的宝箱表记录。负视野目标会被拒绝。已接受的研究未将该计算推广到任意传入的非零视野目标。其选定的探索边界位于战斗之外。

`OpenChest` 检查匹配标志。未设置时提供该行物品；已设置时改为 Nothing。随后，它在**收到物品之前**设置标志、写入开启图块并请求视野更新。开启文本 403 后，若为 Nothing，则显示空箱文本 408。开启标志可以与未持有物品并存；反过来，标志未设置时，即使已经持有该物品，仍可再提供一份。这些记录不实施唯一物品规则。

两件物品均使用普通容量路径，每个携带者有四个槽位：

| 传入的容量状态 | 被调用服务返回时的条件结果 |
| --- | --- |
| Bowie 有空位 | 发现文本 413；加入 Bowie 的第一个空槽位；请求物品音乐与接收文本 415；执行共享的输入／淡入淡出等待并关闭窗口。宝箱标志保持设置。 |
| Bowie 已满，另一名已加入成员有空位 | 重建军团列表；按己方角色顺序升序扫描其他已加入成员；加入第一个有空位者；请求音乐与转交物品文本 416；执行相同完成尾部。标志保持设置。 |
| 所有可用携带者均已满 | 满手文本 417；恢复保存的候选坐标；关闭／回填。`CloseChest` 清除标志、恢复关闭图块并请求视野更新。不添加物品。 |
| 标志已设置或没有匹配记录 | 空结果，不扫描物品栏容量，也不授予物品。 |

其他成员搜索包括已加入的后备成员，且不按 HP 筛选。它依赖普通列表不变量：已加入的 Bowie 排在首位；即使传入的成员状态不一致，最初的 Bowie 容量检查仍是硬编码的。这不是选择物品栏的提示，也不是强制丢弃事务。`AddItem` 用 `$807F` 掩码处理条目，因此接收物品不会自动装备。尽管调用方先检查容量，却忽略后续插入结果；在普通物品栏不变时，两步结果一致，但对已改变或格式错误的状态没有原子性保证。

满容量尾部完成后会恢复可获取状态。Map50 的非宝箱物品表只有终止符，因此在两个选定坐标处，该尾部均没有另一件非宝箱物品可供恢复。开启写入之后的中断，仍可能使 F152/F147 已设置却未取得物品，或已取得物品但音乐／文本／输入尚未完成。宝箱可获取状态、携带者选择和表现是不同的效果。此处未提供通往 Panel 宝箱的外部接近路径，也未提供从它通往 Sword 宝箱的路径。

## 在 Ribble 树前使用 Panel

**已确认的准入：**FieldMenu Item → Use 选择携带者、槽位和物品。Panel 不在普通野外可用物品允许列表中，因此进入地图物品事件分支。事件比较掩码处理后的所选 ID `$70`，以及**物理实体 0 的当前位置与朝向**：

| Map8 物品记录行 | 当前玩家瓦片 | 必需朝向 | 目标 |
| --- | --- | --- | --- |
| 0 | `(15,19)` | Up | `Map8_ItemEvent0` |
| 1 | `(16,19)` | Up | `Map8_ItemEvent0` |

这里既不使用搜索的前方瓦片，也不使用所选携带者的位置。仅在军团某处持有 Panel 并不足够；取消不会调用该事件。坐标、朝向或物品错误时进入共享默认返回。默认城镇配置与 F708 城镇配置共用这些记录；F708/F709 不是额外的 Panel 使用门槛。准入不检查 Peter 是否存在。

F731 已设置时，处理器返回 d6=0，不开启也不移除任何东西。未设置时，完整顺序为：

1. 执行开启脚本 `cs_56314`。
2. **脚本返回后**设置 F731。
3. 重新搜索已加入军团的物品栏，尝试按 Wooden Panel 物品身份移除。
4. 忽略该移除结果；设置已处理 d6=-1 并返回。

任何宝箱标志或预先存在的图块状态检查都不能替代 F731。处理器的十个物理操作与共享返回，和内嵌脚本的 30 条记录相互独立。

## 开启场景请求的内容

**已确认的完整静态程序：**下表涵盖 `cs_56314` 的全部 30 条记录及其两个内联移动体。它不含文本位置或内部跳转。尽管菜单此前停用了实体更新，脚本调用仍会在解释执行之前激活实体更新。

| 记录 | 按顺序执行的场景工作 |
| --- | --- |
| 0–4 | 隐藏文本／立绘；等待 Bowie `eas_Init`，再等待 Peter `eas_Init`；震动 2；Sleep 60。 |
| 5–10 | 开始 Bowie 跳跃但不等待；等待 Peter 跳跃；开始 Bowie Down 2 但不等待；等待 Peter Down 2；让 Bowie 面朝 Up，再让 Peter 面朝 Up。两个内联体均以 `endActions` 结束。 |
| 11–15 | 请求 `SFX_BATTLEFIELD_DEATH`；将源 `(32,17)`、大小 2×2 复制到 `(15,19)`；Sleep 30；震动 0；Sleep 30。 |
| 16–21 | 震动 2；相同 SFX；将 `(34,17)`、大小 2×2 复制到 `(15,19)`；Sleep 30；震动 0；Sleep 30。 |
| 22–27 | 震动 2；相同 SFX；将 `(32,14)`、大小 2×2 复制到 `(15,19)`；Sleep 30；震动 0；Sleep 30。 |
| 28–29 | 请求 Peter→Bowie 跟随，选择器 2；结束。只有此后，调用方才设置 F731 并尝试移除 Panel。 |

`eas_Init` 设置速度 32/32、禁用加速／减速、恢复地图／实体碰撞和自动朝向、清除浸没状态、设置大小 24，并在空闲前更新精灵。`eas_Jump` 禁用自动朝向，以两个 Wait 5 命令分隔三个相对偏移请求，随后恢复自动朝向并进入空闲。每个 Down 2 程序体安装一个相对目标动作。等待形式轮询**该映射行动者的空闲脚本指针**；它们不保证所有行动者同时完成，也不保证移动无阻。Peter 的等待不能证明 Bowie 的上一个动作在下一次安装替换它之前已完成。

动作安装不检查 HP 或是否存在。它解析当前逻辑到物理映射；缺失／默认零或过期的 Peter 映射可能寻址到错误的物理行动者。朝向命令使用己方角色字节，可能跳过 HP 为零的 Bowie/Peter。按字编码的 Peter 随从操作数则具有零高字节：跟随处理器检查的是 **Bowie 的 HP**，不是 Peter 的。Bowie 死亡可使该请求被跳过，而返回的调用方仍标记 F731 和已处理使用。该脚本不会创建行动者，也不会让军团成员加入。

获准的跟随请求解析当前行动者及选择器 2 的 `(-24,0)` 偏移，安装一份复制的 42-byte 随从动作，并在物理随从不在列表中时追加它。避免重复列表条目并不避免动作分配。这不会设置 F67、修复映射、证明分配容量或确立已稳定的跟随；重新生成 Ribble 实体是另一项操作。

每次图块复制都替换 64 列工作缓冲区中的完整布局字，保留其属性，并请求两个视野平面更新。震动 2/0 写入振幅；滚动使用方请求随机水平／垂直偏移和 VDP 更新。这些是源码操作，渲染出的震动、碰撞通行和可听 SFX 仍属未知。Sleep 操作数不是实测经过时间，调试文本跳过状态可以跳过它们。脚本终止时的条件滚动等待与寄存器恢复，既不证明表现完成，也不证明玩家控制已能响应。

## 消耗 Panel、重复与重新加载

**已确认的移除边界：**`RemoveItemFromInventory` 调用 `GetItemInventoryLocation`，后者重建已加入军团并按成员顺序搜索，每个物品栏从其报告的最后持有槽位向下搜索至零，比较掩码处理后的 ID。它使用普通的紧凑物品栏／非空军团不变量；搜索不按出战成员资格、HP 或装备状态筛选。匹配时移除该槽位，将后续条目左移，在最后槽位写入 Nothing 并更新属性值。

所选菜单携带者／槽位**不是**移除目标。存在重复物品时，可能移除另一携带者的一份或另一个持有槽位。失败会返回失败结果，但 Map8 调用方忽略它。此路径不增加诅咒／丢弃确认，也不提供回滚。

| 传入或中断的状态 | 静态边界上的后果 |
| --- | --- |
| F731 已设置，仍持有 Panel | 不开启／移除；进入零结果菜单回退。 |
| F731 未设置，已传入最终开启图块 | 再次请求整个场景；没有基于图块的幂等性检查。 |
| 脚本尚未返回 | 调用方尚未设置 F731／移除／已处理状态；此前行动者、震动和图块阶段可能已经发生变化。 |
| 脚本已返回，F731 已写入，移除失败 | F731 保持设置，d6 仍变为 -1。没有重试／回滚来修复持有状态。 |
| 移除已完成，包装器尚未返回 | Panel 可以已经不存在，而等待／菜单／控制仍未完成。 |

物品包装器保留 d6，关闭窗口、等待一个 VInt，并等待物理实体 0 的位置等于目标位置。非零 d6 退出 FieldMenu。零值请求使用物品文本 73／无效果文本 422，并返回物品子菜单，不自动消耗。后续菜单退出／更新重新激活会到达待处理事件／控制衔接处；传入模式、待处理状态及服务是否返回仍然重要。

重新加载 Map8 时，在基础布局加载后独立应用 F731 标志事件复制：将 `(32,14)`、大小 2×2 复制到 `(15,19)`。它请求最终开启状态，不重放场景或移除。因此，F731 本身既不能证明场景完成，也不能证明 Panel 已消耗。即使此前在内存中执行过复制，清除它后重新加载仍可恢复基础内容。宝箱标志独立恢复开启的宝箱图块。临时标志清除范围 256–383 不包括 F731/F147/F152，但持久的存档／恢复持久性仍未观察。

## 神殿请求与有条件的 Sword 返回

**已确认的选定请求：**Map8 传送记录行 3 使用通配 X255、Y20、无滚动、Map50、目标 `(42,23)`、Up。普通移动必须先遇到工作布局中的传送属性 `$1000`（掩码 `$3C00`）；这条宽泛记录并不使每个 Y20 瓦片都成为出口。它写入请求元组和传送 SFX，不检查 F731 或 Panel 持有状态。开启会替换布局字，但从任一使用位置自然通行仍属未知。

对于保留下来的无滚动请求，使用方清除待处理状态、播放／清除传送 SFX、使物理实体 0 空闲，并向 MainLoop 返回显式元组。地图切换先于战斗选择；Map8/Map50 没有按标志切换的替代地图。树旁的元组本身并不保证进入探索：Map50 有战斗记录行 15，区域为 `(0,0,32,24)`，**通配触发坐标为 `(255,255)`**。`CheckBattle` 检查地图、F415 和触发条件，不检查 `(42,23)` 是否位于该矩形内。

| 传入的进入标志 | 准入结果 |
| --- | --- |
| F415 未设置，F515 为任意值 | 无 Battle15 候选；准入普通探索分支。 |
| F415 已设置，F515 未设置 | 选择 Battle15。此分支在准入处停止。 |
| F415 已设置，F515 已设置 | 选择 Battle15，然后清除 F415；完成标志不会取消已经选定的准入。此处同样停止。 |

Panel/Sword 持有状态及 F731 既不能确立这两个标志的值，也不能证明此前战斗已完成。交战与结果不在本指南范围内。获准探索时，Map50 无地图专属配置，使用 `ms_Void=$FFFF`；初始化／事件包装器跳过这类处理器，而不会选择一个尚未重建的神殿场景。共享进入流程仍会治疗存活／不死己方角色、初始化主要随从与已配置随从、清除临时标志，并在有条件地交还控制之前加载地图／宝箱内容。没有地图专属初始化会授予这两件物品中的任一件。

位于 `(35,6)` 的 Sword 宝箱仍有独立的朝向偏移搜索／容量边界。已接受内容不能证明从 `(42,23)` 到达它、从 Panel 区域到达它或在其他 Map50 区域之间步行。共用存储和战斗区域边界不能重建地形。

选定返回记录行 2 要求 `(42,24)`、无滚动、Map8、目标 `(16,20)`、Down。它不检查 Sword 或宝箱标志。若请求保留下来，相同使用方到达 Ribble，且无 Map8 战斗记录行；重新进入选择按标志选定的城镇配置，在 F731 设置时应用它，并在有条件地交还控制之前运行已接受的 May 相关初始化。传送／重新加载不会移除 Sword。**有条件的成功接收**在此返回之前使所选携带者取得物品；自然步行离开、不间断持有及可用输入仍属未知。

这种持有状态可以满足 Rohde 首次交谈时对已加入成员物品栏的搜索，包括后备成员；Sword 不必由 Bowie 携带或装备。Rohde 的所选物品路径则要求实际选择 Sword，并满足其独立的 `(16,58)` 谓词。F147/F731 不是持有检查，Rohde 也不消耗 Sword。他的选择见[独立 Hassan 指南（英文）](../../synthesis/hassan-ancestry-and-rohde-caravan-choice.md)。本指南停止于有条件的 Ribble 返回／持有状态及该交叉引用，不包含外部神殿接近、Rick、Battle17/18、Rohde 重放或 Caravan 操作。
