## 进程、Scratch 与诊断安全

**时机分类：生命周期要求现在确定；运行器及经过测试的墙上时间值在用户单独启动 Phase-4 后实现。**

未来门禁中的每个外部进程都具有有限、受跟踪的墙上时间预算。精确数值预算随引导实现选择和测试；任何步骤都不得无限等待。每次原生启动均使用参数列表，不经过 shell，并声明工作目录、输入配置、输出根及诊断上限。

超时或取消时，运行器必须：

1. 将失败归因于精确门禁及墙上时间预算；
2. 请求终止完整进程组/树，而非仅直接父进程；
3. 限制终止器进程及其回收时间；
4. 保留直接终止进程的回退；
5. 限制目标进程及管道回收时间；
6. 无法完成回收时关闭捕获句柄；
7. 检查残留的项目所有子进程；
8. 即使之前观察过玩法/导入标记，也发出失败的清理回执。

构建、导入、运行、采集及导出变更使用忽略本地边界或临时 CI 根下新建、经验证的目录。运行器拒绝已存在路径、仓库根、声明 scratch 根以外路径，以及输出所有权不明的路径；不递归删除调用方提供或预先存在的目录。可为有界诊断保留 scratch；须报告其存在，且它绝不能使失败门禁通过。

诊断包含退出状态、超时步骤、准入工具身份、有界 stdout/stderr 尾部、清理操作、残留状态及回执/输出路径；排除凭据、完整私有内容、采集、解码资产及无界日志。

## 纯 C# 状态与薄 Godot 组合

**时机分类：所有权及端口现在确定；场景载荷依赖研究；类型、节点和接线在用户单独启动 Phase-4 后实现。**

`Domain` 返回确定性转移结果与状态事实，不调用观察器、设备、文件、时钟、渲染器或 Godot。`Application` 拥有 `GameSession`、一次一个命令的准入、`GameFlowCoordinator`、呈现提示、确认、应用端口及语义观察信封。`Content` 在创建会话前验证并映射包。

协调器保留 ADR 0011 的架构阶段顺序：`AdmittedStart` -> `Exploration` -> `MapOrProgramTransition` -> `BattleAdmission` -> `BattleInitialization` -> `BattleTurns` -> `BattleOutcome` -> `AfterBattleProgram` -> `ReturnHandoff` -> `StableControllableEndpoint`。这些是**现在确定**的编排边界，不表示精确转移谓词或可选子状态已知。其场景身份、载荷、自然路线、输入序列、程序效果及端点事实**依赖研究**；可执行状态与转移在**用户单独启动 Phase-4 后**实现。

`Sf2.Remake.Godot` 具有一个组合根，创建或接收会话、已验证内容、配置、观察器、资产解析器、输入映射、渲染器、音频及采集适配器。场景只拥有可丢弃视图实例、插值、焦点、资源及动画状态。从一个应用快照重建场景，不能改变玩法。

- 身份、版本、摘要及依赖闭包；
- 重复、范围及准入域检查；

私有 7C 仅本地适配器与公共合成配置使用相同逻辑 ID 及向内端口，但外层解析器、包、输出和声明分离。私有输入缺失或不匹配使精确配置不可用，绝不能回退到合成数据却声称满足 7C/8C。公共 CI 仅使用可安全再分发的测试夹具及项目自创合成内容。两种配置均不授权公开发布原版内容。

## 确定性时钟、RNG 与逻辑输入

**时机分类：抽象及禁止项现在确定；节奏、种子、调用顺序和输入轨迹依赖研究；实现与测试在用户单独启动 Phase-4 后进行。**

未来应用接收显式确定性时钟、RNG 转移及逻辑输入边界。整数模拟步和单调序列号为玩法排序。交互墙上时间只可在 Godot 适配器中为已经决定的步骤调节执行节奏。

`Domain` 或 `Application` 中的玩法不得依赖：

- `System.Random`；
- Godot 随机数生成器；
- 系统时间、时间派生种子或隐藏可变流；
- `_Process` 或物理 delta time；
- 线程调度、区域设置或无序集合迭代；
- 动画时长、音频完成或渲染帧率。

RNG 操作接收显式状态和调用族输入，返回结果、下一状态及有序观察事实。精确算法行为仅依据已接受所有者实现。种子、完整到达调用顺序、副本/重试行为、确定性节奏、逻辑输入轨迹、输入重复时序及物理设备时序仍**依赖研究**。

Godot `InputMap` 将键盘和控制器输入转换为语义方向、确认、取消及菜单行动。设备映射仍为适配器配置。应用决定逻辑行动是否可在当前流程状态准入。H4 使用与手动游玩相同的逻辑边界，不能直接注入领域变更。

已接受 [Godot AI 探针](../../../../../tools/godot-ai-probe/README.md)是一次性能力与工具证据。其安全、有界的经验包括：

- 在 scratch/构建/导入变更前检查精确 Godot 版本；
- 将声明的受跟踪输入复制到新建忽略 scratch 根；
- 分开构建、编辑器导入及无头运行门禁；
- 为每个外部进程施加有限墙上时间限制；
- 终止进程树，并限制终止器/目标回收及管道清理时间；
- 限制诊断，要求断言完成输出，而非仅零退出。

以下探针细节不具规范性，不得复制为生产架构：

- 其单项目布局及节点所有的模拟；
- `System.Random`、其种子/结果，以及其 60-`_Process`-frame stdout 黄金输出；
- 其目标框架、.NET 宿主观察、SDK 或本地编辑器路径；
- 其 GL Compatibility 渲染器选择；
- 其精确九文件 scratch 清单；
- 其应用/程序集名称变通方案；
- 其探针场景、位置、分数或输出字符串；
- 其缺少锁定还原、包审计、导出门禁、十层 H4 回执及四项目架构测试的状态。

未来运行器可以复用进程安全要求，但必须是在单独启动后编写和审阅、由项目拥有的生产工具。探针项目绝不移入 `remake/`，也绝不成为实现依赖。

## 提议验收门禁

**时机分类：本文件切片现在确定；这些是文档门禁，不是 Phase 4 实现门禁。**

Phase 1 要求：

- 恰好一个受跟踪路径：本新文档；
- 每个本地链接都针对已接受 `main` 解析成功；
- 英文规范文本，无意外汉字，代码围栏/表格/Mermaid 平衡，差异/空白干净；
- 无私有/生成/二进制载荷、本地机器路径、凭据、ROM、采集、提取资产或可执行工具；
- 每个章节和表格保留**现在确定**、**依赖研究**或**用户单独启动 Phase-4 后**分类；
- 不虚构测试夹具/schema/研究索引关联、路线、状态、种子、命令、采集哈希、可观察值、比较域或容差；
- ADR 0011 程序集名称/依赖及就绪十层顺序保持精确；
- 设计合同及研究索引计数不变；
- Ruff、共享原生测试台、正常仓库验证、依赖规划及 Public 受跟踪输入检查通过；
- 不为本次仅设计新增运行旧 full 配置。

严格 zh 元数据验证属于后续共享注册，因为 Phase 1 刻意不编辑 zh 清单。若当前 74 篇已翻译/零待翻译基线不变，将本源加入为待翻译会使注册分母成为 75 篇：74 篇已翻译、1 篇待翻译。此未来计数不属于 Phase 1 验收。

## 提案效果

**时机分类：现在确定。**

接受本综合会使未来 Phase 4 引导可供审阅，但不会使场景就绪或启动实现。它不会创建项目、选择已接受 Godot 4.7.2 之外的工具链、安装或运行 Godot、采用 MCP、填充 H4、授权私有内容再分发，或改变任何 Research 缺口。

就绪台账对最终连续里程碑验收仍为 **NOT READY**。R1-R4、连续场景合同、完整 H4 定义、私有输入验收及主门禁就绪仍是该目标的要求；按 ADR 0016，单独用户授权可以更早启动有界实现切片。
