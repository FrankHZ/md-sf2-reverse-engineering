**已确认：** 未变的新初始化之后，即便队伍不触发三个区域中的任何一个，Battle26 十五名存活敌人也可进入行动顺序。其 STARTING 模式也产生空生成列表。区域激活、生成与单次行动资格是独立规则。最终首个行动者依赖实际队伍、当前敏捷与连续 RNG；本指南止于首次调用 ExecuteIndividualTurn，早于任何单次行动执行。

## 首次调用之前发生什么

**已确认：** 新回合前缀按以下顺序。后步要求先前调用服务返回；静态顺序不建立可见时序。

| 步骤 | 选定操作 | 建立的事实 |
| --- | --- | --- |
| 1 | ActivateEnemies | 扫描敌人激活候选，包括额外槽 160 顺落。 |
| 2 | ExecuteBattleRegionCutscene | 扫描完整区域钩子表；当前 Battle26 不匹配任何行。 |
| 3 | 测试 DEBUG_MODE_TOGGLE.b | 零跳过诊断；非零在生成前调 PrintAllActivatedDefCons。 |
| 4 | PopulateTargetsListWithSpawningEnemies | 写字列表长度；只有非空列表按存储顺序为字节 ID 调 SpawnEnemyWithCamera。 |
| 5 | GenerateBattleTurnOrder | 填充、追加并排序两字节单次行动记录，再清当前行动字节。 |
| 6 | 读一个战斗员字节 | CURRENT_BATTLE_TURN 是缓冲区字节偏移。ID 255 回步骤1；其他 ID 到 ExecuteIndividualTurn。 |

分发读取不读分数，也不重检 HP、位置、成员资格、激活、中立状态或控制类型。此调用前无战斗结束测试。它证明以可到达为条件的函数交接，不是已返回行动、玩家就绪菜单或已完成 AI 单次行动。

调试分支检查十六标志 F90–105。每个持有标志将区域索引写 DIALOGUE_NUMBER、请求文本463、恢复/递增索引，最后关文本。这些是诊断文本服务调用，不是激活写入或诊断文本出现的证据。调试字节非零时，其完成是额外前提。

## 区域与激活不同于单次行动资格

**已确认：** ActivateEnemies 从敌人 128 开始，至 159 共执行 32 次普通辅助调用。每次先拒绝有符号 X 为负，再拒绝当前 HP 为零，再拒绝战斗员 ID 字节非负。不测试 Y、成员资格、中立状态、移动命令或指令集。符号位已设的非零 HP 通过此 HP 测试。

消费者准入规则与边界不同：

| 消费者 | 考虑槽 | 实际位置/HP 门槛 | 其他重要边界 |
| --- | --- | --- | --- |
| 普通敌人激活 | 128–159，再额外160 顺落 | 有符号 X 非负；HP 字非零；ID 字节为负 | 无 Y、成员资格或 neutral 位排除。 |
| 可触发几何的己方 | 全部 30 槽0–29 | HP 字有符号正值；有符号 X/Y 非负 | 不使用出战资格或敌人/中立槽。 |
| 生成列表构建 | 全部 32 槽128–159 | 以下模式相关门槛 | 初始化位不同于 active 位。 |
| 单次行动列表构建 | 己方0–29，再敌人 128–157 | 有符号 X 非负；HP 字非零 | 无 Y、成员资格、neutral、active-region 或指令集测试。 |

因此变化后的存活已布置己方槽即便不是当前出战成员也可触发几何。有符号负 HP 不能触发几何，却能通过 HP 非零的激活/行动检查。32 个激活候选与 30 个敌方行动候选不能当作相同名册边界。

已接受新状态中，敌人 128–142 为正 HP、已布置 X。缺席143–158 不通过激活 X 门槛。completion526 未设时，中立159 的 X18/Y14、HP 0，因此因 HP 而非 neutral 位测试失败。持有526 时改为 X=-1/HP 0。前序拥有这些条件中立写入。

## 额外激活遍历为何能触及特卖存储

**已确认：** 32 次调用循环后 d0.w 为160，d7.w 为65535。循环和紧随辅助标签之间无 RTS、分支或生成数据。执行再顺落一次辅助；其 RTS 返回 BattleLoop。选定布局在行动顺序函数前包含完整此文件。函数结束注释不生成返回指令。

实际战斗员地址辅助用 `bhi` 拒绝字节 ID 大于 160，因此160 通过包含上界。减 96 得存储索引 64；`64*56` 加战斗员基址得到 `0xFFF600`、CURRENT_GOLD，紧邻 `0xFFF604` 的 DEALS_ITEMS 之前。这是重叠地址，不是分配的敌人。选定伪字段为：

| 伪字段 | 实际打包特卖解释 |
| --- | --- |
| X，偏移 46 的字节 | 物品 84/85 数量；位 7 使伪 X 为负并拒绝辅助。 |
| 当前 HP，偏移 14 的字 | Protect Ring20、Quick Ring21、Running Ring22、White Ring23 数量；零字拒绝。 |
| 触发，偏移 54 的字节 | 物品 100/101 数量成为主要/次要区域半字节。 |
| 激活，偏移 52 的字 | 物品 96–99 数量；低位属于 Goddess Staff99。 |

特卖解码器选 `DEALS_ITEMS+floor(item/2)`，偶数物品在高半字节，奇数在低半字节。若伪 X 通过、ring 数量字非零，且非15 伪触发引用持有 F90–104 标志，普通激活设置器向 Goddess Staff 数量 OR 位 0，或在次要路径 OR 位 0/1。其他数量位保留；已设位未必改变数量。这是条件位写入，不是无条件加 staff、饱和递增、商店事务或已观察购物证明。

未变新 Battle26 中，F90–105 已清，无几何设置它们。即便其他特卖字节符合，也找不到持有触发标志，因此额外调用不写特卖。变化位置/标志/特卖可改变结果；同前缀更早激活写入已可见。[研究别名连接](../../../research/battle26-activation-and-first-turn-dispatch.md#the-extra-fall-through-and-its-selected-ram-alias)保留精确地址/getter/setter 和指令溯源；源码 BUG 注释本身不是证明。

### STARTING 不是 hidden 或 respawn

**已确认：** 生成构建以计数 0 开始，按序扫描32 槽128–159。用 `0x0F00` 掩码每个激活字。模式 0 立即跳过，早于任何 HP、区域、位置、物品或重置调用。十五行均用 STARTING0；定义优先级占 `0xF000`，激活仅改位 0/1。因此升级定义或触发区域不改变这些行生成模式。

缺席143–158 为 0；159 为 0 或中立 8，掩码后也为0。全部 32 候选跳过，TARGETS_LIST_LENGTH.w 变 0，BattleLoop 不调生成服务。旧列表字节未清，但长度 0 不消费它们。该分支无物品重置、重生计数器、摄像机、出现文本、声音或动画。

变化状态必须走实际模式分支：

| 掩码模式 | 重置前准入 |
| --- | --- |
| Hidden `0x0200` | 当前 HP 0，加持有非15 主要/次要触发；激活辅助成功返回 0 而非 -1。最大 HP 也须为 0。 |
| Respawn `0x0100` | 当前 HP 0；无区域要求。 |
| Hidden+respawn `0x0300` | 同样死亡/触发辅助成功，无额外最大 HP 测试。 |
| 其他非零模式 | 不匹配选定分支，不追加。 |

重置要求真实行：Battle26 计数 15 给战斗员排他上界 143。它用全部 30 己方和 32 敌人 X/Y 检查行起点，无 HP、neutral 或自我排除过滤。仍在自己起点的死亡槽可阻挡自己。无效行或起点被占写最大/当前 HP 0、X=-1、带 carry set 返回且不追加。成功复用 InitializeEnemyStats，包括条件升级/当前属性/物品，恢复保存的完整激活字并带 carry clear 返回。仅之后调用者才追加 ID 字节并递增字长度，按扫描升序。

后续模式比较用返回 d1、完整恢复字，不重新掩码模式。成功 hidden 重置保留 `0x0200` 模式，不匹配之后 respawn 或组合分支；成功 respawn 保留 `0x0100`，不匹配组合分支。其他 active/优先位不改变区别。每个选定成功槽追加一次。源码顺落不建立重复追加或单调递增生成计数器。

初始化器保留物品边界：row 2 成功插 Black Ring 经 AddItem 剥离编码装备/AI 使用/掉落位，普通 NOTHING 行保留复制装备。这是复用初始化器，不是独立生成奖励；新模式 0 完全阻止这些重置写入。

变化后的非空列表中，SpawnEnemyWithCamera 用零摄像机选项、保留外层遍历寄存器、调实体生成、清光标半径、选视野目标、请求光标目标并等待后隐藏光标。十二次迭代请求 orientation `(d7+3)&3`、d2=d3=-1 与 Sleep3，之后生成音效、战斗员名称索引、文本397 和关闭文本。这些是服务与循环计数边界，不是模拟摄像机/动画、观察时序或已完成出现。不据此推断其他战斗生成。

### 当前敏捷与连续 RNG

**已确认：** 当前 AGI 按无符号字节读取。令 `A=rawAGI & 0x7F`，`R(n)` 为范围 n 的下一 GenerateRandomNumber 结果：

- 首分数：`A + R(A>>3) - R(A>>3) + R(3) - 1`。
- 若 rawAGI>=128，立即为同 ID 追加第二记录。其基础为 `B=floor(A*5/6)`，分数为 `B + R(B>>3) - R(B>>3)`，无最终 R(3)-1。
- 字运算只存结果低字节。拒绝候选不消费抽取；单记录候选消费 3 次，双记录消费 5 次，按槽顺序。

每次调用将字种子更新为 `(seed*13+7)&0xFFFF`，包括范围 0。这些小范围结果为使用更新后种子的 `floor(seed*n/65536)`。直接辅助保留 d6.w，绕过调试方向覆盖。三次抽取是连续状态变化，不是独立选择值。
