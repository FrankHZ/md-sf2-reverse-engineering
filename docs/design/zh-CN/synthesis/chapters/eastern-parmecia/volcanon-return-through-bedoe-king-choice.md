# Volcanon 返回至 Bedoe 国王选择

> 本文是[规范英文原文](../../../../synthesis/chapters/eastern-parmecia/volcanon-return-through-bedoe-king-choice.md)的中文镜像；英文始终为审阅基线，翻译遵循[术语表](../../../../glossary.md) R1–R7。已译指南与合同使用中文导航；未译相邻指南标明英文，研究与源码仍由英文所有者提供。译文不产生新观察或扩大原版/重制边界。

返回 Bedoe 后，国王询问 Bowie 是否接受 Volcanon 击败 Zeon 的要求。接受会引出关于 Creed 的建议，并请求 Luke 离开安排木筏。拒绝会收到留在 Bedoe 的提议；接受后的后续互动则仅提供鼓励。台词、Luke 局部离开与调用方标志写入是独立结果。没有一项确立木筏已准备或可用。

**已确认静态内容与控制流：**已接受的[研究所有者](../../../../../research/chapters/eastern-parmecia/volcanon-return-through-bedoe-king-choice.md)支持下文选定返回请求、提示与行动者/服务边界。**推断：**这是[神殿觐见](bedoe-to-volcanon-audience.md)的可选内容接续。**未知：**自然楼层旅行、实际传入状态、输入/服务完成、表现与可玩连续性。本指南不增加重制能力或产品决定。Fnnn 表示标志 nnn；坐标为地图瓦片，另注者除外。

止于首次选定国王回应、调用方完成和条件控制交接。Bedoe 出口、Polca 抵达或木筏服务、雏鸟/Skreech/救援、Luke 招募及 Battle13 仍在范围外。建议的旅程是有归属的建议，不是已确立路线。

## 返回 Bedoe 与选择变化后的配置

**已确认选定请求：**两个 Map11 传送行描述返回区分条件：

| Map11 匹配点 | 不滚动请求 |

| X8，Y34 | 显式 Bedoe/Map10，目的地 `(45,50)`、Down。 |

两行都不测试 F722、F799、成员资格或朝向。Down 是抵达请求，不是前提。当前地图目的地不证明步行至 `(8,34)`，也不自行产生下一请求。移动产生方需要布局属性掩码为 `$1000`；有序行匹配使用由每瓦片 384 内部单位得出的瓦片坐标与负坐标通配符。待处理消费在分发前清除事件 type。不滚动使用方请求声音、将 main 置为待机，并将地图/位置/朝向返回主循环。Map10/11 没有选定按标志切换替代或战斗地图行，因此请求独立于战斗解锁选择探索，并假定当前地图行仍为 Map11。

探索入场治疗存活/不死己方角色并淡入淡出。当前地图请求更新 main 与木筏/随从放置，加载地图并运行 init，同时保留固定实体群与映射；Map11 init 仅返回。显式 Map10 入场加载选定配置、重建映射与实体群，再经过地图/VInt/init 服务。入场治疗不证明行动者存在，也不证明之后互动时 HP。

仅 F722 选择 Bedoe 替代配置，包括实体、实体事件、zone 事件和 init；描述与物品事件共享。每次配置查找重新解析当前标志。神殿调用方仅在脚本返回后写入 F722：仅听到部分觐见不确立此选择。F722 未设的传入状态保留默认配置。入场和 F722 写入不自动调用国王互动；F799 不选择配置。

## 与国王交谈不要求面向 Down

**已确认普通激活：**C 在调试/车队替代后走实体激活路线；A 打开菜单。首先将 main 置为待机，并等待 physical 0 当前/目的地坐标及视野滚动。激活使用当前视野目标及朝向寻址一瓦片，跨越柜台瓦片继续，排除视野目标/列表内随从，并取距寻址点曼哈顿距离小于 384 内部单位的首个实体。视野目标为负/无匹配不进入成功路径。正常视野目标为 physical 0；自然访问国王仍为**未知**。

普通国王用例要求被激活物理行动者反向映射为查找 147。有序反向查找、回退查找 0、不匹配或别名映射可选择另一事件。替代事件行编码查找 147 和 `DOWN=3`。使用方匹配查找后将第二字节解释为位，不测试国王或玩家是否面向 Down：

- 位 0 等待一个 VInt，并将映射行动者朝向设为传入玩家朝向字节的反向，即 `(playerFacing+2)&3`。
- 位 1 在调用方返回后恢复所保存物理行动者互动前的朝向。

包装器将玩家朝向存为 `EVENT_RELATIVE_POSITION`，从当前映射精灵选择台词属性。正常 KING_BEDOE 提供立绘 NONE 和 `DIALOG_BLEEP_7`；改变精灵/映射可改变选择。这些是服务输入，不是观察到的表现。它在调用方之前禁用实体更新。脚本的 trap 在执行带等待行动前独立启用更新；拒绝/重复不调用该 trap。

作为对照，默认 F722 未设行编码 147、`UP=1`，请求 text1678，没有 F799 测试或提示。它将行动者转向玩家，但不恢复保存朝向。替代选择自身也没有独立 F720/F721 前提。

## 问题、拒绝与重复回应

**已确认调用方内容：**F799 未设时，国王说 Volcanon 已抛弃地面居民（1603），继而询问 Bowie 是否会按要求杀死 Zeon（1604）。调用方调用实际感知输入的 `j_YesNoPrompt` / `YesNoPrompt`，不是替代入口或脚本 `yesNo`/F89 服务。

| 状态或提示结果 | 选定回应 |
| --- | --- |
| F799 未设；确认 Yes，D0 字为 0 | 运行接受场景 `cs_5797A`；脚本成功返回后设置 F799 并返回。 |
| F799 未设；确认 No 或 B 取消，D0 字为 `-1`（`$FFFF`） | 国王提议留在 Bedoe（1605），并声称这里安全（1606）；返回，无场景、Luke 行动或 F799 写入。 |
| F799 未设；没有确认输入 | 提示保持待处理；没有返回结果或自动接受。 |
| F799 已设 | 国王祝领队好运（1614）；无提示、场景或 F799 写入。 |

调用方对任意非零 D0 字分支，但提示通常仅返回 0 或 `-1`。无法通过该返回区分 No 与取消。拒绝使本调用方 F799 保持未设，因此后续符合资格互动可再次提问。国王的安全保证是有归属的台词，不是保护规则。

提示以 Yes 选中开始。它快照 `PLAYER_1_INPUT`、打开/加载提示、移动现有对话/金币窗口并等待移动。入场快照非零时，需要 `PLAYER_1_INPUT` 归零才进入输入循环；零快照绕过释放循环。循环按 Left、Right、B、C、A 顺序检查 `CURRENT_PLAYER_INPUT`。Left 选择 Yes，Right 选择 No；单独方向不退出。B 选择 No 并退出；C/A 确认选中字节。同一采样中方向优先于按键。初始 Yes 仍需确认。无输入则动画/VInt/循环工作保持待处理，没有超时或第三种返回选择。关闭/删除提示后，将字节符号扩展为返回字。

**未知：**实际释放/边沿时序、同时采样输入、窗口完成与可见选择。静态输入顺序不测量时序或确立自然传入结果。

## 接受：Creed 建议与 Luke 离开请求

**已确认有序场景：**游标 1607 提供八条文本请求 1607–1614，king 147 七条、Luke 10 一条。加上上述五个调用方位置，共为 **13 个请求位置、12 条不同文本**：结尾 text1614 由接受与重复共享。研究保留完整 16 条记录台账（15 条操作码命令加终止符）及两个内联体；全部内容如下：

1. 请求 Peter 面向国王。国王赞许选择并建议找 Creed（1607），称 Creed 曾是 greater devil，或可提供信息（1608），指引沿河前往其宅邸（1609），并说 Polca 或许有木筏（1610）。
2. 国王面向 Right，下令通知镇长准备木筏（1611）。Luke 第一段带等待行动移动 Up2，再 `faceLeft 1`；Luke 接令（1612）。
3. Luke 第二段带等待行动移动 Down3、Right1、Down4，之后场景隐藏 Luke。请求国王面向 Peter，让 Peter 帮助领队（1613），并祝领队好运（1614）。脚本结束；只有成功返回才到达调用方 F799 写入。

Creed 历史、建议河流路线和可能的木筏仍是国王说法/建议。Luke 接令与局部离开不确立向镇长传话、抵达 Polca、木筏准备/可用或地图转移。脚本内部没有提示、故事标志写入、加入、跟随、出战队伍/AI 变化、传送、实体重载或招募。Peter 的 F7/F39、Luke 的 F10/F42、军团 AI 与 F67/F75 保持传入值。

两个 `faceEntity` 命令解析当前字查找，并比较**目的地** X/Y 的绝对差值。相等时垂直优先；目的地相同选择 Down。更新第一行动者精灵/朝向并等待一个 VInt，**两行动者都没有 HP 守卫**。这不同于字节行动者 `setFacing`，后者己方准入测试字 HP；本场景唯一 `setFacing` 使用 NPC147，绕过该己方测试。因此 Peter/Luke HP 为零不跳过这些朝向/行动/隐藏/文本请求。场景不治疗或复活。

查找解析掩码为字节、NPC128+ 减 `$60`，再将映射物理索引乘以 32。零映射解析为 physical 0；`$FF` 无有效性守卫就解析为索引 255。因此 F67 未设的 Peter 可使 physical 0 转向。行动/隐藏/朝向通常不验证存在，不能将已隐藏或别名 Luke 描述为安全跳过。

每个 `entityActionsWait` 先用 `$9F` 掩码行动者标志再安装行动指针，然后等待该指针等于 `eas_Idle`。这不是全体行动者屏障，也不证明路径无阻挡。相对移动从当前位置加入有符号瓦片差值乘以 384；`faceLeft 1` 是朝向/精灵/等待工作，不是向左一瓦片。场景不规定 Luke 起点坐标。**推断：**固定放置有效、移动完成且服务正常时，Luke 隐藏前运算为 `(38,51)` → `(38,49)` → `(39,56)`。F75 跟随或位置改变使固定起点叙述失效；终点不是观察结果。

## 隐藏、返回与重入有不同边界

**已确认隐藏服务：**`HideEntity` 将 Luke 当前/目的地 X/Y 写为 `$7000`，将 64 字节映射列表中每个匹配物理索引条目置为 `$FF`，并前移后续条目以移除匹配随从列表条目。它不清除 F75、成员/出战标志或军团 AI，也不抹除行动/行进字段。当前 X 至少 `$7000` 时，实体更新/行动分发跳过。成功且映射互异时，两个行动都已到达带等待的待机边界；隐藏自身不完成行进。别名映射会扩大失效范围。这不同于之后 F799 选定的仅坐标 init。

文本服务选择立绘/台词并等待滚动/文本；单文本额外关闭窗口并 sleep 10。调试跳过独立。没有独立 sleep 记录不意味着耗时为零。终止符在文本窗口仍在时有条件等待滚动并清除滚动速度，既不设置 F799，也不设置控制。

| 传入或部分状态 | 结论限制 |
| --- | --- |
| 脚本在隐藏前停滞 | F799 保持未设；Luke 已安装/完成行动取决于已到达位置。 |
| Luke 已隐藏，但最终文本/脚本返回未完成 | 隐藏 Luke、失效映射可与 F799 未设共存。不能保证重试是安全重放。 |
| 新 F722 选定 init 之前 F799 已设 | 重建提供当前实体群，随后 init 将 Luke 移出地图而不使映射/列表状态失效，即使 F75 将其声明为随从。 |
| Init 后 Luke 仍在时 F799 改变 | 重复调用方仅请求结尾文本，不重跑移除或修复行动者。 |

接受脚本成功返回后，调用方设置 F799。任何调用方分支完成后，事件包装器恢复**所保存物理国王行动者的已保存朝向**、关闭立绘/文本窗口并启用实体更新。即使映射改变，保存行动者仍是目标。因此最后面向 Peter 请求不保证互动最终朝向：国王映射普通且未变时恢复 Down，传入互动前朝向不同则恢复该值。不同于 zone 包装器，该实体包装器不增加调用方后的 main 停止等待。

`ProcessPlayerAction` 返回探索。`WaitForEvent` **仅在待处理地图事件 type 为零时**将摄像机重新指向 0，并安装 physical 0 的受控行动；另一待处理请求优先。`PLAYER_TYPE=0` 选择 `eas_ControlledCharacter`，其他类型选择各自行动。调用方/窗口/VInt 服务完成及待处理为零确立该条件交接，不是观察到输入响应。仅 F799 不证明上述任何条件。止于此处。
